## 怎么打开

```bash
cd game
pnpm dev
# 浏览器打开 http://localhost:5173/first-hall/
```

没有 pnpm 也能看，用任意静态服务器把 `game/public/` 当根即可：

```bash
cd game/public
python -m http.server 8765
# http://127.0.0.1:8765/first-hall/
```

⚠ **不能直接双击 `index.html`**：`file://` 下浏览器会拦截 `/models/*.glb` 的加载，页面会提示用 http 打开。

## 操作

| 输入 | 作用 |
| --- | --- |
| `W A S D` / 方向键 | 沿视线方向在地面漫游（带殿内边界，撞墙会分轴滑动，不会穿出去） |
| `Q` / `E` | 降低 / 升高视点（限 0.9–2.6 m） |
| `Shift` + WASD | 加速（2.1 → 4.4 m/s） |
| `R` / 双击画布 / 「居中构图」 | 复位到进门机位 |
| 左键拖动 / 滚轮 | 旋转 / 缩放（**视角锁在殿内**，怎么转都不会跑出房间） |
| 右键 | 平移已禁用（见下文 v7：pan 会把旋转中心带出殿外） |
| 点 3D 物件（烛台 / 经幡 / 柜门 / 香炉 / 卷册） | 切换五处差异。**默认不圈、不列对照、不报「差几处」，也不给答案按钮** —— 得自己拿镜中画面跟实景比 |
| **点殿中的镜子** | 满屏雾涌、涟漪荡开、实景沉入雾后，旧景从雾里由远及近显影浮出；再点一次收起 |
| **空格**（照镜时按住） | 暂时收起画幅看实景，松开回来，来回比对最方便 |
| `Esc` / 点画幅 / 面板按钮 | 收起旧景画幅 |

漫游是沿相机水平朝向走的，不是第一人称转身；转视角仍用鼠标。`canStand()` 约束了四面墙、四根柱和镜面，v7 的 `keepInside()` 再把鼠标旋转／缩放产生的相机位置也夹进同一个安全盒，所以左键拖到极限也只是「顶住墙」，不会转到殿外。详见后文 v7。

## 三档资产（URL 参数切换）

| 参数 | 目录 | 面数（整幕 18 实例） | 体积 | 用途 |
| --- | --- | --- | --- | --- |
| 默认（包内含） | `/models/low/` | 约 32.5 万 tri | 11 MB | 整幕漫游、网页流畅、发评审 |
| `?q=lod`（包内不含） | `/models/lod/` | 约 300 万 tri | 39 MB | 中距离看材质，贴图已降 512² |
| `?q=hq`（包内不含） | `/models/` | 约 300 万 tri | 94 MB | 2048² 原版，近景单件验收，**别用于整幕** |

`low` 版由 `make_lowpoly_glb.py` 用顶点聚类生成：几何之外一律不动，UV 取格内首个合法值（不做平均，避免 atlas 串色）；`lod` 版由 `make_lod_glb.py` 只把贴图 2048²→512²，几何逐字节不变。三个脚本都在工作区 `lux3d_assets/`，本场景包在 `tools/lux3d/` 留档。**本场景包是轻量转发版，只含默认 `low/` 六件（约 12 MB）**；`lod/` 与 `/models/` 原版需从本机工作区或 `第一殿_最终交付包_20261113.zip` 补齐。原版 `spec_ready/` 始终保留，但不在本包里，也不参与网页整幕默认加载。

## 其它 URL 参数

| 参数 | 作用 |
| --- | --- |
| `?clean=1` | 隐藏常规 UI，只留场景（照镜画幅仍保留），用于出图 |
| `?solved=1` | 直接摆成「镜中样」，展示镜面裂开 + 半印落下 |
| `?vision=1` | 进页面就直接展开旧景画幅，用于实拍 / 快速体验 |
| `?debug=1` | 显示帧数 / draw call / 三角形数 / 加载路径 / 相机坐标 / 按键 / 离屏纹理抽样 |
| `?cam=x,y,z` | 自定义机位（走近看细节 / 出图用），视线仍对准殿心；如 `?cam=1.9,1.55,1.7` |
| `?lite=1` | 关阴影与照镜，软渲染诊断用 |
| `?clean=1&vision=1` | 交付图里的「照镜浮现」构图（稳定薄雾态） |
| `?mist=burst` | 用静态样式定格「雾中显影」那一瞬，出图 / 复核用 |
| `?mist=0` | 关掉全部云气与显影，回到 v4 的静态硬边画幅，做对照 |
| `?hints=1` | **内部复核用**：恢复五个序号圈、五列「镜中/实景」对照、差异状态与「摆成镜中样」按钮。默认玩家看不到 |
| `?orbit=az,pol,dist` | 出图诊断：把相机绕 target 转到指定方位角 / 极角 / 距离，验证 `keepInside()` 仍把它夹在殿内。如 `?orbit=2.6,0.50,6.2` |

`?debug=1` 下另挂 `window.__walkProbe(n)`（同步推进漫游）、`window.__visionProbe(bool)`（展开/收起画幅并返回状态）、`window.__orbitProbe(az,pol,dist)`（转到极限角度并返回 `{cam, target, inside}`），供无头浏览器做确定性验证，正常游玩不会用到。

## v4 照镜画幅（11-14）

**要解决的问题**：v1–v3 把「进门之前」的殿贴在一面 Ø1.88 m 的圆盘上，且用的是镜后固定机位 —— 画幅小、构图与实景对不上、五处差异根本看不出来；绕到侧面看还像一张贴在镜面上的图，不自然。

**改法**（依旧零生成、零积分，GLB 未动）：

| 项 | 做法 |
| --- | --- |
| 触发 | 点殿中镜子（镜面圆盘或镜框），浮出旧景画幅；再点画幅 / 镜子 / `Esc` / 面板按钮收起 |
| 定格 | 照镜那一瞬复制玩家机位，把场景临时摆成 `TARGET`（进门之前）离屏渲染 960×600；画幅是「过去的一张画」，之后走动不跟着转 |
| 呈现 | `renderer.readRenderTargetPixels` → 逐行翻转 → DOM `<canvas>`，铺在屏幕空间的描金画框里。**不贴在镜面几何上**，绕到侧面仍是正对玩家的规则矩形 |
| 镜面 | 本体换成暗青铜镜（浮锈 / 云雾 / 淡符印），只留常驻细裂纹与通关裂纹；不再承载任何房间画面 |
| 可读性 | 画幅里五个序号圈标出差异位置（用定格相机投影）；底部五列对照「镜中 / 实景」+「合 / 不合」，切换实景实时刷新；旧景轻微提亮，像蒙了一层冷光（**v6 起默认隐藏，见下文**） |
| 比对 | 照镜时**按住空格**暂时收起画幅看实景，松开回来；因为画幅会遮住实景中央，这一步最实用 |

旧景里保留了「镜中有、实景无」的一双绣花鞋（只在离屏渲染时显形）。五处全合时画幅与实景构图完全一致、对照条全变青绿「合」，就是「形已核」的视觉表达。

**实拍验证**：初始态 / 通关态 / 侧面机位 `?cam=1.9,1.55,1.7` 三张照镜图，画幅均正常显示旧景、不贴面、不穿帮；debug 抽样 `rt=23,46,38,255` 确认离屏纹理有内容。踩过的坑：先用 scissor + 正交 quad 把 rt 贴回屏幕，结果画幅纯黑（quad 未显示），改成 DOM canvas 后一次通过。

**已知妥协**：画幅遮住实景中央，靠空格透视 / 走动 / 对照条弥补；「保存画面 PNG」会把 DOM 画幅合成进图，但描边与文字是 UI，不入图。

## v5 云气显影（11-15）

**要解决的问题**：v4 的旧景是「啪」地弹出一整块规整矩形，太像弹窗、太死板，没有「镜中幻象」的神秘感。

**改法**（依旧零生成、零积分，GLB 未动；全部是程序化 Canvas 贴图 + CSS 动画 + 7 片 3D 雾 sprite）：

| 项 | 做法 |
| --- | --- |
| 显影 | 点镜子瞬间重启 CSS 动画：旧景由 `blur(12px) / brightness(.5) / opacity .28 / scale(1.07)` 在 1.35 s 内收敛到清晰；画幅自身从 `scale(.955) + translateY(18px) + blur(9px)` 浮入 |
| 涌雾 | 3D 镜前 7 片加色雾 sprite 从镜心向外飘、上浮、放大再淡出（2.4 s）；离屏渲染旧景时临时隐藏，不拍进画幅 |
| 雾边 | `makeEdgeMaskDataURL()` 生成 512×320 遮罩：四边线性羽化 + 大尺度低对比云团起伏，`mask-image` 把画幅啃成不规则雾边；底板改青灰，避免半透明处露出黑斑 |
| 常驻云气 | 两张反向流动的雾纹理（大团 + 细缕 + 卷云纹）铺在 `#visionMist`；`#visionVeil` 用 5 个边缘软云团 + 四边 inset 雾影做出「云气从四边涌进来」，中央留空；一道冷光 9 s 扫过；画幅 7 s 极慢浮动 |
| 外溢 | `#visionAura` 比画幅大一圈，用径向遮罩收成柔和椭圆雾晕，看起来是「从镜里漫出来」而非一块弹窗 |
| 导出 | 「保存 PNG」把两层雾纹理 + 四边雾带一起 `screen` 合成，不会导出成无雾版 |

**结构上的关键一点**：云气层必须放在 `#visionImage`（带云雾遮罩）**之外**。第一版把 `#visionVeil` / `#visionSweep` / `#visionBurst` 放在里面，结果刚加的边缘雾又被遮罩擦掉，稳定态看着仍是一张干净照片；挪到 `#visionFrame` 直接子层后四边云气才真正可见。

**出图参数**：`?clean=1&vision=1` 稳定薄雾态；`?clean=1&vision=1&mist=burst` 用纯静态样式定格显影瞬间（整幅浓雾、柔焦、半显）；`?clean=1&vision=1&mist=0` 无雾对照。`clean` 出图模式把所有持续动画静态化、并跳过 3D 雾涌 —— SwiftShader 软渲染下逐帧 `blur` + 多层 `screen` 混合会让无头截图跑不完虚拟时间（实拍时带雾图连续超时，定位后解决）。**正常游玩不受影响**：显影、云气流动、扫光、浮动、镜前涌雾全部照常。

**实拍验证**：9 张 1440×900 图（初始 / 通关 / 诊断 / 近景 / v5 照镜三态 / 显影瞬间 / 无雾对照）。稳定态四边云带明显、中央旧景与五个序号圈及五列对照清晰；显影瞬间整幅浓雾柔焦，像幻象；侧面机位画幅仍正对屏幕、不贴面。无灰屏、过曝、穿模。

### 2. 雾从「画幅边」扩到「整个视野」

| 层 | 作用 |
| --- | --- |
| `#visionFog` | **满屏雾墙**，`inset:-14%`，大团浓雾 + 擦空隙 + 卷云纹（`makeFogDataURL()`）。混合从 `screen` 改回 `normal`：之前只是给画面盖一层亮纱，现在是真的把「现在」遮进雾里 |

| `#visionRipple` | 一圈圈从镜心荡开的时空涟漪 |
| `#visionMotes` / `#visionDrift` | 浮尘与极缓的雾团漂移 |
| 显影 | 旧景由远及近微推近、柔焦 → 清晰；雾边遮罩收一档，不再把画面四角啃掉太多；`?mist=burst` 定格那一瞬 |

**踩过的坑**：第一版满屏雾用 `mix-blend-mode:screen`，稳定态成了一块灰白硬矩形；改成 `normal` 雾墙并补青灰雾底、把雾边擦除收一档后才像雾。天花格线与拜石过亮也一并压暗。第二版雾太满，把画幅内部也洗成灰绿，旧景与实景糊成一片、五处差异根本读不出来 —— 于是把 `#visionMist` / `#visionDrift` 的径向遮罩中心留空从 16% / 22% 扩到 44% / 46%，`clean` 出图时两层不透明度降到 `.40` / `.28`：**雾仍铺满整个视野，但只在画幅四边翻涌，中央旧景保持清楚**，玩家才可能自己看出不同。

`body:not(.hints)` 隐藏 `#visionMarkers`（五个序号圈）、`#visionCompare`（五列对照）、`#diffList`（差异状态）、`#solve`（摆成镜中样）。题头只留一句氛围叙述，**不报「差几处」、不指向任何物件、不给答案**。玩家只能自己点镜子、按住空格在旧景与实景之间来回比对、去点殿里的东西试。`?hints=1` 才恢复全部提示与状态，供内部复核与验收出图。

## v7 视角锁内 · 公堂陈设补完（11-15，当前版本）

### 1. 修掉「转视角转出房间」

**根因**：殿只有 12 × 12 × 4 m（墙在 ±6、天花 4.1 m），但 `OrbitControls` 给的是 `maxDistance = 18`、`enablePan` 默认开、且没有 `minPolarAngle`。于是滚轮一拉远、视角一抬头，或右键把旋转中心平移出去，相机就跑到墙外／天花以上 —— 那里什么都没建，只剩漆黑虚空。

**改法**（`app.js`）：

| 项 | 旧 | 新 |
| --- | --- | --- |
| `enablePan` | 默认 `true` | `false` —— 右键平移会把 `target` 推出殿，相机便绕着殿外的点转 |
| `minDistance` / `maxDistance` | 1.6 / **18** | 1.2 / **6.2**（默认机位到 target 约 5.7 m，只留一点拉远余量） |
| `minPolarAngle` / `maxPolarAngle` | 0 / .495π | **.30π** / .505π —— 不许俯冲到天花以上，也不许钻到地板以下 |
| 每帧位置约束 | 无 | `keepInside()` 在 `change` 回调里把相机夹进 `WALK` 安全盒（±5.35 m、y .95–2.85 m） |

**夹取方式（v7.1 修正）**：v7 最初只夹相机、不动 `target`，这其实破坏了 OrbitControls 的球坐标 —— 下一帧 `update()` 从被夹扁的半径重算，相机会一帧帧缩向 `target`、最后钻进公案／镜台里，看起来像「整个房间不见了」。v7.1 改成把夹取量同步加到 `target`，保持 `offset = position - target` 不变：视线方向不变、半径不塌，拖到边界只是「顶住墙」转不动。WASD 本来就是两者同步平移，不受影响。

验证：`?orbit=az,pol,dist` 出图参数 + `window.__orbitProbe()`（`?debug=1`），实拍了极限仰角与极限侧转两张图，相机均被夹回殿内、画面仍是殿内墙与天花。

## v7.1 修复「连房间都进不去」（11-15，当前版本）

**现象**：打开页面后一直停在「准备中…／载入证物 5 / 6」或整屏「场景未能启动」，房间根本出不来。无头浏览器抓 DOM 实测 `<div id="loading">` 始终没有 `done`。

**根因**：`boot()` 把「揭幕 + 启动渲染循环」放在 `H.loadAssets().then()` 里，6 件 GLB 用 `Promise.all` 一把梭 —— 只要有一件请求挂起、超时或 404，`then` 永不执行（或 `reject` 后只弹失败页），遮罩就永远不会消失。殿宇和灯光其实在 `init()` 里早就搭好了，只是被这层黑遮罩盖住。

**改法**：

| 位置 | 改动 |
| --- | --- |
| `app.js` `boot()` | `init()` 后先单独 `renderer.render()` 出**一帧房间**，不等 GLB；**1.2 秒无条件揭幕**，遮罩点一下也能立刻跳过 |
| `app.js` `boot()` `catch` | 资产异常不再锁死整幕：同样揭幕 + 起循环，只给一条轻提示（不再整屏失败页） |
| `scene.js` `loadAssets()` | 逐件超时／失败**占位跳过**，`Promise.all` 不再 `reject`；缺哪件只是少一件证物 |
| `scene.js` `inst()` | `inst(null)` 返回空 `Group`，摆放逻辑不抛错 |
| `scene.js` 出图模式 | `?clean=1` 逐件超时放宽到 60 s：无头浏览器的 `--virtual-time-budget` 会快进到短定时器，提前触发 rAF 空转会拖垮软渲染截图 |
| `app.js` `keepInside()` | 夹取量同步加到 `controls.target`，修掉上面说的球坐标塌陷 |

**没有把渲染循环整体提前**：无限 `requestAnimationFrame` 会从页面加载第一刻就占住软渲染／无头截图，实测把出图从 22 秒拖到 5 分钟超时。所以只在加载阶段出**一帧**，持续循环仍由资产回调启动。

**验证**：默认页 DOM 变成 `<div id="loading" class="done">`；`?clean=1` 出图 18 秒完成；重拍默认机位、极限仰角、极限侧转三张，相机仍锁在殿内。

## v7.2 视角自愈 · 万能回殿键（11-15，当前版本）

**现象**：实拍反馈是「几乎全黑，只剩殿外墙角、一块亮柜门和甬道石板，题头还在」—— 相机停在殿外／墙角往里看，那里既没有几何也没有灯光。复现 `?vision=1` 照镜稳定态是正常的（画幅、雾、面板都在），所以不是照镜暗幕单独造成的。

**三个叠加原因**：

1. **缓存／旧标签页**：预览面板可能一直拿旧的 `app.js`（还没有 v7 的 `keepInside()`），或页面是改代码之前就打开、从没刷新过 —— 于是「转出房间」依旧，我这边带 `&v=7c` 破缓存的实拍却一直正常。
2. **启动流程里的同步首帧**：v7.1 为了「先出一帧房间」在 `boot()` 里同步 `renderer.render()`，实测在无头／软渲染下会把整页拖到 150 s+ 无响应；带 `?clean=1` 的页面不出这帧，16–23 s 就正常出图。
3. **复位不彻底**：旧 `goFront()` 只挪相机，不清 `body.vision`；若正卡在照镜状态，满屏 `#visionDim` 暗幕还在，按 `R` 看起来也没进房间。

**改法**：

| 位置 | 改动 |
| --- | --- |
| `index.html` | `scene.js?v=8` / `app.js?v=8` 破浏览器缓存；交付链接同样带 `?v=8` |
| `app.js boot()` | 去掉启动流程里的同步 `renderer.render()`，改成揭幕时**一次性异步 rAF** 补帧（不占住渲染循环） |
| `app.js boot().then()` | 资产到位后**无条件 `goFront()`**，每次进页面都从殿中央起步；`?cam=` / `?orbit=` 诊断参数在其后照常覆盖 |
| `app.js goFront()` | 升级为**万能逃生键**：清 `vision` / `peek`、清残留按键、复位相机与 `target`、同步按钮文字 |
| `app.js tick()` | 每帧检查相机，越界（±5.95 m、y 越界）或 `NaN` 立即 `goFront()` |
| `index.html` | 常驻「**回殿中 · R**」按钮（左下角，z-index 20 盖过照镜暗幕），`init()` 之后立刻绑定、不等资产；底部提示写明卡住按 R |
| URL | 新增 `?reset=1` —— 强制回殿的链接参数，等价于按 R |

**怎么用**：任何时候画面变黑、只剩墙角、或照镜退不出来，按 **R**／**双击画面**／点左下角「**回殿中 · R**」都能一次性退出照镜并回到殿中央。若怀疑是旧缓存，直接打开带 `?v=8` 的新链接或 `Ctrl+F5` 强制刷新。

## 五处差异怎么玩

旧景画幅**不是贴在镜子上的贴图**，而是点镜子时定格、离屏渲染的一幅独立画面。镜中固定是 `TARGET`（进门之前），实景由玩家切换；两者同机位同构图，差异才读得出来。渲染旧景时单独点一盏补光，不影响实景的低调布光。

| 差异 | 交互 | 引擎侧 |
| --- | --- | --- |
| 烛台方位 | 点击任一支 / 面板第一项 | `rotation.y` 90° 步进 |
| 经幡顺序 | 点击任一面 | 挂序 + 长短，实例化改 scale |
| 柜门开合 | 点击任一扇 | 左铰链 pivot，`rotation.y` ±0.46π |
| 香炉有无 | 点击香炉 | `visible` |
| 卷册朝向 | 点击任一卷 | `rotation.y` 0° / 180° |

**v6 起默认不给提示**：没有序号圈、没有五列对照、没有差异清单、不报「还差几处」，题头只有氛围叙述；玩家得自己反复照镜、按住空格来回比对、去殿里点东西试。`?hints=1` 才恢复上述全部提示（内部复核用）。仍保留「重置陈设」「保存画面 PNG」「居中构图」「照镜 / 收起」四个按钮；「摆成镜中样」只在提示模式出现。

五处全合 → 镜面裂纹 decal + 朱红半印从镜后落下 + 一句「镜面裂了」的叙述（不解释哪里对了）。

**按需渲染**：静止时不重绘，只在视角或状态变化时跑一小段阻尼帧。旧景只在照镜那一刻渲染一次（定格），不随每帧重算，软件渲染也扛得住。

2. 孽镜照见一生善恶，无可抵赖。可这面镜子不映人，只映这座殿。（剧本 · 考据 / 场景）
3. 镜中是「你进门之前」的模样，与眼前有五处不同——把它们摆回镜中样子，镜面才肯裂开。（剧本 · 谜题）
4. 镜碎那刻，你会拿到第一枚半印，和第一桩证据：你死时，房里空无一人。（剧本 · 产出）

行为：揭幕后承接对白先亮，串联态约 1.2 秒 / 独立进入约 350ms 后接上旁白；
每句约 4.6 秒自动推进，点字幕可手动推进 / 跳过，「重听旁白」按钮可重播。
不占任何游戏按键，渲染与解谜逻辑一行未动。
`clean` 出图一律不播不显（DOM 存在但 CSS 隐藏 + `introStart()` 直接 return），13 张定稿图不受影响。

普通 `INTRO lines=4 first=第一殿，秦广王座 advanced=true clean=false dom=true`；

## 纸扎人造型：像人，但不脱画风（v16）

mina 反馈「这些人有点假」+「画风要与整体一致」。查证后定的原则是：
**「像人」靠形体比例与站姿，不靠画脸。**

- 《纸嫁衣》系列里最瘆人的视觉形象是「**类人**」纸扎人——「与人外形类似，
  但四肢僵硬」；让人发毛的是「它没动」，不是五官。
- 纸扎民俗铁律「**不点睛**」：扎纸匠不扎眉眼，一点即赋灵。与 v3「面壁无点睛」、
  负面词「五官清晰的纸人」完全同向。
- 《千与千寻》无脸男：无脸却极有「人」的存在感，靠大驼背、垂袖、低头、静止的姿态线。

所以**没有加脸、没加脸谱朱砂、没引入新颜色**，全部改动在剪影与材质：

| 原来（假） | v16 |
| --- | --- |
| 矩形薄板 + 圆球 + 两根垂直方条 | `Shape` + `ExtrudeGeometry` 人形纸壳：领口凹、肩线斜、收腰、袍摆 A 字外张且毛边不齐 |
| 零厚度立牌 | 2.6 cm 进深；顶点按 x 位移鼓成微凸弧面，侧面另有纸翼，不再是平板 |
| 一根直筒袖 | 上臂 / 前臂两段 + **肘部折角**，喇叭袖口中空、内壁暗 |
| 纯色白球头 / 白袖，比身体亮一大截 | 新增 `M.folkPlain` 中性糊纸纹（同底色、同纸纤维、无骨架十字），头 / 袖 / 袍身统一灰白旧纸 |
| 五个一模一样的复制品 | `FOLK` 五组参数：不等距站位 + 身高 / 胖瘦 / 前倾 / 低头 / 歪肩 / 袖摆 / 侧转差异；`lux3d.js` 的 `FOLK` 表已同步，GLB 到位后不会退回复制粘贴 |
| 头顶浅色小圆柱亮成「白帽子」 | 移除口沿，靠纸纤维贴图破光滑感 |
| 脚下亮白纸灰像白色垫子 | `folkAsh` 压到 `0x4b524c / opacity .26` |

另：柱础原用受光材质，朝上被顶部冷白灯直照过曝成白块，且正落在纸扎人脚边容易被
误读成底座。染色诊断确认归属后改用不受光的 `MeshBasicMaterial` 锁定亮度，
与窗外冷雾、白纸灯笼同属一个冷白光色系统。

完整参考出处与举证口径见根目录《Aholo_Lux3D_资产举证清单_全作品.md》§7.1。

## v24：脸、衣服层次与转动流畅度

mina 接着提「人好歹有个脸和衣服吧」「屏幕转的也不流畅」「衣服参考动漫里的，太粗糙了」。
仍按「画风要与整体一致」收口，分三块改：

**① 脸：有，但不点睛**

- 5 人中 3 个面壁只见素白后脑，2 个侧过身来，贴一张**椭圆毛边糊纸脸**
  （`Shape` 26 边 + 径向渐隐融进头壳）：淡眉、杏仁形**空眼窝**、鼻梁糊缝、一道平直嘴线；
  不点瞳、不上朱砂、不做脸谱。
- 脸片必须贴在球头正面 `z≈.142`（球半径 `.132 × scale.z .76 ≈ .100`）。
  第一版放在局部 `z=1.012`，等于飘在 0.77 m 外 —— 这是当时「一张脸都看不见」的真正原因。
- v24 把五官压痕整体加深一档（alpha `.12→.22` / `.20→.34` / `.17→.30`），近景才读得出「有脸」。

**② 衣服：层叠纸片，不是贴图上的线**

参考《纸嫁衣》系列的汉服版型与现实纸扎「一层层糊纸」：云肩（四瓣如意弧）、
双层交领右衽、宽腰带与菱形纸结、两条斜剪飘带、摆缘包边、外翻袖缘，
**两面都糊**（面壁的看 -z 面、转身的看 +z 面）。

- v20 第一版层叠纸片用纯色 `MeshStandardMaterial`，正对冷白灯被过曝成
  「白塑料铠甲 / 机器人」，比原来更跳画风。v21 新建 `M.folkCloth` 糊纸纹，
  四个层叠材质统一带同一张纸纤维，靠 `color` tint 拉
  「缘边最深 → 腰带 → 折棱 → 内衬最浅」的明度阶梯，最浅也只比袍身亮一档。
- v22 把袖子从**上窄下阔的圆锥漏斗**改成**四棱柱 + 几何空间转 45° + 压进深 .44**
  的平直方形宽袖，肩头也由球形改成一片折方纸。压缩必须在 `geometry` 上做：
  若用 `mesh.rotation + mesh.scale`，压缩方向会跟着转 45°，袖子会扭成斜菱形。

**③ 转动流畅度（`app.js`）**

- 根因：`OrbitControls` 旋转中心原本在走廊深处 10.4 m 外，而廊宽只有 6.4 m，
  转约 18° 相机就撞 `keepInside()` 边界被硬夹回去、target 还跟着漂，于是「转不动、一顿一顿」。
  现在 `aimAt(AIM)` 保持**视线方向不变**（所有机位构图不变），但把旋转中心压到相机前方
  `LOOK_DIST = 1.05 m`；`minDistance/maxDistance` 收紧到 `.90 ~ 1.35`，`rotateSpeed .85`。
- 第二个卡顿源：旧 `tick()` 只在「还有帧可渲」时才调 `controls.update()`，
  松手后 `enableDamping` 的惯性被冻住。现在每帧都 `update()`，其返回值直接当续帧信号；
  静止时才跳过 `render` 省资源。
- 顺手关掉 `preserveDrawingBuffer`（截图改由 `savePNG()` 在同一同步栈内 render 后取像素），
  像素比上限压到 `1.25`。

### ⚠ 与 v3「无清晰文字 / 无字教程」的边界

对白是 **DOM 字幕层**，不往水牌、木牌、墙面贴图写字，场景内仍无清晰可读文字；
台词只讲剧情与世界观，不含「下一步点哪里」的引导 —— 教学链依旧靠物件微光 +
4 个纯图形槽位驱动。`?nodlg=1` 一键回纯无字版；
`?clean=1`（出图）与 `?probe=1`（探针）由 `OFF` 强制关闭，
`dialogue.js` 连 DOM 都不注入，纯净定稿图与教学链验证不受影响。
这是**叠加的、可关的剧情层**，不是对 v3 的破坏；v3 原文未改动。

## 启动与踩过的坑

**必须经 http 打开**：在 `superagent/game/public` 跑 `python -m http.server 8765`，
访问 `http://127.0.0.1:8765/prologue/`。不要双击 `index.html`。

- **GLB 绝不阻断揭幕**：第一殿踩过「6 件 GLB 全部成功才揭幕，一件挂起就永远停在
  `载入证物 5 / 6`」的坑。序厅 `init()` 搭完建筑壳就揭幕，Lux3D 资产在
  `boot()` 里异步挂载；先用 `HEAD` 探测文件是否存在，缺件 / 超时 / 解析失败
  一律静默跳过并保留程序化占位，绝不把玩家关在门外。
- **外壳换成「不可见但可命中」的代理**：GLB 顶替程序化外观时，原 mesh 不是
  `visible = false`（那样 raycaster 与 `?probe=1` 都会漏掉），而是换成
  `opacity .001 / colorWrite false` 的代理材质，形状与包围盒保持不变。
  摇柄、两半路引、半印、香段、冷火这些**动画部件**保留原样，仍由引擎驱动。
- **启动流程里不做同步 `renderer.render()`**：第一殿 v7.2 实测这一帧会把无头 /
  软渲染拖到 150 s 超时。序厅揭幕后由按需渲染循环出第一帧。
- **静止不重绘**：`invalidate(n)` 只在视角 / 状态 / 动画变化时跑有限帧，避免无限 rAF
  占住 SwiftShader；`?clean=1` 把时间冻结在 0，CSS 层也不放无限动画。
- **窗框别旋转**：窗面在 y-z 平面，宽沿 z、厚沿 x；给框条加 `rotation.y = π/2`
  会把 2 m 长的木条转向 x、伸进走廊，实拍像百叶窗。只有窗纸需要转。
- **窗纸用不受光的 `MeshBasicMaterial`**：窗外那盏 SpotLight 会把 Standard 材质的
  闭扇也照成亮白，六扇就分不出「只开一扇」。
- **窗洞后的暗背板必须 `fog: false`**：这是「六扇全发白」的真正根因 ——
  `MeshBasicMaterial` 默认参与线性雾，远处的暗背板被雾洗成灰白，看起来六扇都透光。
  窗纸与所有雾幕同样关掉二次雾化。
- **无 envMap 时别用高 metalness**：铜件会被渲染成纯黑，本幕压到 .10–.12 并补一点自发光。
- **雾层各自 clone 贴图**：共用一张 texture 时 UV 偏移动画会互相覆盖。

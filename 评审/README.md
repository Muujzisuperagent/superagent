# 视觉评审流程 · 3d-critique

本目录存放《还魂路引》各场景的正式视觉评审。评审依据 `.agents/skills/3d-critique/`，项目美术要求以根目录 `场景生图提示词_v3_恐怖版.md` 为准。

评审只回答“画面是否达到目标”，不证明功能、性能或可玩性通过。

## 与 huihun-eval 的分工

| 层 | 技能 | 作用 | 输出 | 能否判通过 |
|---|---|---|---|---|
| 视觉细评 | `3d-critique` | 十项审美、问题定位、修改动作 | `评审/<场景>/<版本>/` | 否，只给“修改后复审” |
| 正式验收 | `huihun-eval` | 构建、单测、截图、性能、glTF、画质 + 100 分 | `评审/四五六殿/<日期>-<哈希>/` | 是，≥80 且无硬门槛失败 |

- 本目录不替代 `huihun-eval`；两份结论冲突时以 `huihun-eval` 为准。
- 本目录的 P1/P2 是视觉严重度，不等同 `huihun-eval` 的 P0/P1/P2 分数档。
- 本目录的 0–4 分只在本技能内比较，不折算成 100 分，也不能写成“通过”。

## 何时做

- 每次场景改动并重新生成截图后。
- 进入下一殿开发前。
- 提交比赛材料前。

## 目录与版本

```text
评审/
  <场景>/
    v1/
      review.md      评分、问题、修改动作、复验条件
      pixels.json    audit_img.py 原始量测
    v2/               新一轮，禁止覆盖 v1
```

场景名固定为：`四殿药局`、`五殿九宫阵`、`六殿忘川桥`。版本按复审轮次递增。

## 步骤

1. **出图**：`cd game && node tests/visual-check.mjs`，得到 `game/artifacts/act4-medicine.png`、`act5-palace.png`、`act6-reincarnation.png`。需要入口/出口机位时补拍，不能只靠一张图评导航。
2. **先看后测**：先打开原图，按 rubric 写优点、问题、位置、影响、动作、置信度；此时不看像素结果。
3. **像素体检**：

```powershell
& 'C:\Users\lenovo\AppData\Local\Programs\Python\Python314\python.exe' `
  '.agents\skills\3d-critique\scripts\audit_img.py' `
  'game\artifacts\act4-medicine.png' --scene 四殿 `
  --out '评审\四殿药局\v1\pixels.json'
```

`--scene` 可选：序厅、一殿、二殿、三殿、四殿、五殿、六殿。

4. **合成**：十项 0–4 分；无证据填 `n/a`，分母只算已评分项 ×4；不设自动通过线。结论只能是：通过 / 修改后复审 / 证据不足。
5. **落盘**：`review.md` + `pixels.json` 放同一版本目录；新版本开新目录，不覆盖历史。
6. **交接**：每个问题写成“位置 → 动作 → 复验条件”；更新 `sessions/STATE.md`；按仓库规则提交推送。

## 评分与分级

| 分数 | 含义 |
|---|---|
| 4 | 有证据的出色实现 |
| 3 | 符合目标 |
| 2 | 基本可用但需修改 |
| 1 | 明显问题 |
| 0 | 有证据的严重失败 |

| 级别 | 定义 |
|---|---|
| P0 | 阻断核心交互或严重画面故障，且有实际证据 |
| P1 | 主目标难以辨识、显著风格违约 |
| P2 | 局部光照、材质或构图问题 |
| P3 | 微调 |

单个像素比例不能直接定 P0/P1；所有量测告警需人工复核。

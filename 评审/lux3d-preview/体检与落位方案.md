# Lux3D v2 四件 GLB 离线体检与落位方案

工具：Blender 4.5.9 无头（EEVEE Next 渲染 + 松散件分离 + 顶点探针）、gltf-transform 4.5.1（全局已装）

## 结论先行

1. 四件全部**真几何、可直接用**：抽屉格/铜环、9 块独立石板、拱洞/券石/望柱/石狮、花头-茎-土盘相连，均非贴图假象。材质 `metallicFactor 0.1 / roughnessFactor 1` + 内嵌 2048² baseColor/metallicRoughness，**没有旧四件 metalness=1 发黑问题**。
2. 两个必须处理的形态坑：**nine-palace-v2 原始姿态是竖立的 3×3 石屏风**（板面在 X-Y 平面），落位必须放倒；**四件包围盒都是归一化尺度**（0.15~3.0 单位），不是米，必须按实测包围盒换算缩放。
3. 载入成本实测：prune（删未用法线贴图）+ WebP + meshopt 后 **66.96 MB → 10.40 MB（-84.5%）**，解码器在 `three/examples/jsm/libs/meshopt_decoder.module.js` 本地已有，**零新增依赖、零联网**。推荐四件全启用。
4. 落位参数已用 Blender 按游戏等价机位预演渲染验证（`placement-*.png`）：九宫放倒后踩板阵列比例正确、石桥桥头人眼机位坡道/栏杆比例正确且桥面标高与现有 `floorHeight` 正弦吻合（桥头 0.220 / 桥冠 2.020）、百子柜双实例夹 2.9 m 门洞落地、彼岸花簇落地生根。

### 关键问题逐件回答

**herbal-cabinet-v2（百子柜）**
- 抽屉格：**真几何**。每面 7 列 × 7 行 = 49 抽，**双面都有抽屉**（±Z 两面）；格档亮木条、抽屉面板、铜环均为独立松散件（共 3,935 件）。
- 铜环：**有几何**，环尖凸出到 ±0.2804，面板面在 ±0.26 附近；+Z 面浮雕更深（前面板组件厚 0.040 vs 背面 0.014）。
- 朝向：**正面 = +Z**（浮雕深、铜环带青绿锈色更立体）；背面 -Z 也是抽屉面（贴墙无害）。
- 顶部有 cornice（ crown 线脚）；**无药签纸签**（需程序叠加或接受无签）。
- 预览：`herbal-cabinet-v2-front/back/side.png`。

**nine-palace-v2（九宫）**
- **9 块独立石板 ✓**（3×3，缝约 0.002 单位），但**原始姿态是竖立屏风**：板面在 X-Y 平面、厚度沿 Z（0.0299）。`nine-palace-v2-top.png` 看到的"三块一排"是屏风顶缘，`persp` 才是 3×3 全貌。
- 每块板由约 150 个松散壳组成（面板 + 风化剥落 chips），**不能按节点选单块板**；踩板反馈必须继续走程序覆盖层（现有 `markPalaceStep` 机制可复用）。
- **无数字刻字**（渲染与 README 双重确认）；表面湿青灰石 + 苔斑，**非彩釉** ✓。
- 板中心距 0.0509、板面约 0.048 → 换算后与现有 2.05 m 踩板间距天然对齐（见落位表）。
- 预览：`nine-palace-v2-top/front/persp.png`。

**stone-bridge-v2（忘川桥）**
- 拱洞：**真几何、可看穿**（`front.png`）；拱腹券石带放射缝 ✓、 spandrel 拱肩墙 ✓、两端**台阶坡道** + 桥冠平石板 ✓、栏板 + 望柱 ✓、**4 只石狮**在桥头 ✓。
- 实测比例（local）：长 3.0 / 高 1.2314 / 宽 1.1327；桥冠面 z=+0.2796、桥头面 z=-0.4595、拱腹冠 z=+0.0895、底 z=-0.6157、望柱顶 +0.6157；z=-0.45 处拱洞半宽 0.5754；桥面净宽约 1.086。
- 高跨比 0.4105 → 按 20.4 m 长等比会得 8.37 m 高，**必须非均匀压扁**（y 向 2.436 vs x 向 6.8）；压扁后拱矢跨比 ≈0.103，与现有正弦拱 1.8/20.4≈0.088 接近。
- 预览：`stone-bridge-v2-front/side/persp/top.png`。

**spider-lily-v2（彼岸花）**
- **成簇 ✓**（约 12 茎一簇）；花头连茎 ✓、茎插进底部土盘 ✓（土盘半径 0.154、底部 2 cm 内 35,237 顶点，非悬空）。
- 整簇 0.550 × 0.520 × 0.528；血红卷瓣 + 外伸蕊丝 ✓，与参考图形态一致。
- 预览：`spider-lily-v2-front/persp/top.png`。

## 二、落位参数表（游戏世界坐标，已 Blender 预演验证）

缩放语义沿用 `scene.ts:2052-2068` assets 数组（`size` = 目标包围盒，`nonUniform` 逐轴除实测包围盒）。

| 资产 | position | size（目标包围盒） | rotation | 实例 | 替换策略 |
|---|---|---|---|---:|---|
| herbal-cabinet-v2 | [-3.45, 2.42, -7.02] 与 [3.45, 2.42, -7.02] | [4.0, 4.35, 0.76] | 0 | 2 | 纯 GLB；隐藏 `medicine-cabinet-fallback` 整组 |
| nine-palace-v2 | [0, 0.13, -27.75] | [6.05, 0.24, 6.05] | **先 layFlat：model.rotateX(-π/2)** | 1 | GLB 石板 + 程序刻字/踩板反馈叠加 |
| stone-bridge-v2 | [0, 1.339, -62.4] | [4.3, 3.0, 20.4] | longAxis:'z'（rotY 90°） | 1 | GLB 主体 + 程序桥台/灯笼/脚印/亡魂保留 |
| spider-lily-v2 | 河岸 8–10 簇，见下 |  uniform scale 1.442（簇高 0.75 m） | 随机 yaw | 8–10 | GLB 前景主簇 + 程序 `addLilyField` 减量补中远景 |

换算明细（实测包围盒 → 缩放因子）：
- 柜：sx=4.0/1.3004=3.076、sy=4.35/1.3=3.346、sz=0.76/0.5608=1.355。抽屉格换算后 0.571 m 宽 × 0.621 m 高，铜环凸出 ≈0.046 m。双实例夹 x±1.45 门洞（与现程序柜分段完全一致），共享几何只 +1 draw call。
- 九宫：layFlat 后实测 dims=(0.15, 0.0299, 0.15)；in-plane 40.3×（0.0509×40.3=2.051 ≈ 现有 2.05 踩板间距）、厚 8.04×（0.0299×8.04=0.24）。板顶 0.13+0.113=0.243，低于刻字 0.255 与程序反馈板顶 0.25 ✓。**只隐藏 `this.stones` 九块，不得隐藏 `nine-palace-fallback` 整组**（历史坑）；刻字、脚印、碎石、案台、八盏铜盏、布幡、匾额全保留。
- 桥：sx=20.4/3.0=6.8、sy=3.0/1.2314=2.4362、sz=4.3/1.1327=3.796。桥冠 1.339+0.2796×2.4362=**2.020**、桥头 1.339-0.4595×2.4362=**0.220**，与 `floorHeight`（0.22+sin×1.8）端点/冠点精确吻合；拱腹冠世界 y≈1.557，水面 -0.55 上净空 2.1 m。GLB 底 -0.161 高于水面 0.39 m → **保留并下延程序桥台墩到 -0.6**。GLB 栏杆在 ±2.06（现程序望柱 ±2.35）→ 灯笼托架 x 改 ±2.06。
- 花：uniform 1.442；河岸簇 ground=-0.2 → posY=-0.2+0.26×1.442-0.02=**0.155**（土盘入土 2 cm），x=±(9.2..14.1)、z=-47..-75；桥头两岸簇 ground=0.035 → posY≈0.39，x=±(2.65..7.25)、z=-48.4..-51.6 与 -72.8..-76.2。`addLilyField` 240 簇建议减到 120 簇作中远景填充，避免与 GLB 主簇重复抢戏。

### 默认路径切 GLB 时 scene.ts 需要的改动（下一轮实施，本轮不动）

1. `loadAssets` 去掉 `?glb=1` 门槛（`scene.ts:2050`），v2 四件默认加载；**回退方向反转**：程序兜底默认可见，GLB 成功 place 后才隐藏目标子件（现 2116 行"默认 visible=false"是反的，加载失败会留空洞）。
2. assets 规格加 `layFlat?: boolean`（place 内 Box3 之前 `model.rotateX(-Math.PI/2)`）与同文件多实例缓存克隆（柜 ×2、花 ×N 共享 geometry/material）。
3. `materialProfiles`（2069-2074）**不要套用到 v2**：v2 的 metallicRoughness 贴图逐像素调制，标量覆盖会破坏 authored 0.1/1 因子；旧四件 profile 仅留给旧文件。
4. 九宫踩板反馈沿用 `markPalaceStep`（1904-1918）：程序板作为 emissive 覆盖层临时可见，顶 0.25 高于 GLB 板顶 0.243，7 mm 间隙无 z-fight 风险。
5. 桥：灯笼托架 ±2.35→±2.06；桥台墩下延；脚印/亡魂 y 仍用正弦（GLB 台阶与正弦偏差 ≤0.1 m，验收时目视复核）。
6. 柜：`medicine-cabinet-fallback` 整组可隐（门洞立柱 room() 775-776 已有）；`openTray`/heroBowl/`sideCabinet`/bench 均在组外，保留。药签如需要按 GLB 7×7 格距（0.571/0.621 m）重摆 InstancedMesh。

## 三、载入成本与转码实测（本机 gltf-transform 4.5.1，未联网未装包）

管线：`prune`（删未用贴图）→ `webp` → `meshopt --level medium`；实测字节：

| 资产 | 原件 | prune | +webp | +meshopt | 备注 |
|---|---:|---:|---:|---:|---|
| herbal-cabinet-v2 | 14.71 MB | 12.92 | 6.80 | **2.09** | |
| nine-palace-v2 | 11.64 MB | 10.69 | 5.41 | **1.49** | |
| stone-bridge-v2 | 18.69 MB | 16.90 | 10.38 | **3.24** | draco 对照 **1.51** |
| spider-lily-v2 | 21.92 MB | 18.97 | 9.91 | **3.58** | |
| 合计 | **66.96** | 59.48 | 32.50 | **10.40（-84.5%）** | 桥换 draco 则 8.67 |

- 推荐组合：**四件全启用**（用户硬要求 GLB 视觉占比 ≥50%，四件正是三殿主视觉），统一 meshopt（单一解码器、解码快）；`GLTFLoader.setMeshoptDecoder(MeshoptDecoder)`，解码器模块本地 `game/node_modules/three/examples/jsm/libs/meshopt_decoder.module.js` 已存在。draco 解码器亦在 `libs/draco/gltf/`，如要再省 1.7 MB 可桥单独 draco，但双解码器不值。
- 首屏影响：现 0.56–0.67 s；10.4 MB 异步加载不阻塞首帧（程序兜底先可见），本机 localhost 可忽略；弱网约 +1–2 s，可接受。
- 几何账：四件合计 842,614 tris（柜双实例再 +186k）。若 FPS 回退，先 `gltf-transform simplify --ratio 0.6` 减花/桥（meshoptimizer 内置，无需联网），本轮未跑。
- 转码测试副本在 `%TEMP%/lux3d-transcode-test/`（未进仓库）；正式转码下一轮落到 `public/assets/generated/webp/` 并更新 manifest。

## 四、风险清单

1. **九宫竖屏姿态**：不 layFlat 直接落位会立出一面 6 m 石墙挡路——预演已验证放倒参数，实施时务必带 layFlat。
2. **回退方向**：现加载失败静默 + 默认隐藏程序件 = 空洞；切默认 GLB 时必须反转可见性逻辑。
3. 九宫单块板不可选（1,364 松散壳/9 板）：踩板高亮只能程序覆盖层，别试图按 GLB 节点做反馈。
4. 桥台阶 vs 正弦碰撞面 ≤0.1 m 偏差：亡魂/脚印可能微浮/微陷，验收目视复核。
5. 柜双面抽屉：背墙一面也是抽屉面，贴墙无害但别把背面当"柜背"穿帮机位。
6. meshopt 需解码器接线；未接线时 GLB 加载失败 → 依赖风险 2 的反转回退兜底。
7. 未用法线 PNG 不 prune 白背 7.5 MB；`KHR_materials_specular` 为可选扩展，three 不支持时忽略无害。
8. Blender 工具坑（已修，仅影响脚本）：glTF 导入器 `rotation_mode='QUATERNION'` 使欧拉赋值无效；多实例导入时 transform_apply 会误烘焙旧物体——`place_preview.py` 已按"只处理新导入物体"修复。

# 还魂路引 · 四五六殿验收打分表 v2.0（合并版）

本表把两套标准合并：

- **旧版 3D 审美评审**：十项，每项 0–4 分，缺失证据标 `n/a` 并调整分母。
- **新版工程验收**：资产合规、逐幕清单、可玩流程、性能、交付，以及硬门槛与返工线。

旧十项原样保留，每项折算为 5 分，共 50 分；其余 50 分给工程与流程。**不重复计分**：旧项评“好不好”，逐幕清单只评“有没有、结构对不对”。

## 0. 适用范围

- 只评 **第四殿药局、第五殿九宫阵、第六殿忘川桥** 及这三幕的群核资产接入。
- **序厅与前三殿由队友负责，不计分、不扣分**；只在“集成风险”提示。
- 评的是 `game/` 当前 `HEAD` 与本次截图/报告，不评设计文档本身。
- 每次重改必须全量重跑；不允许只补评修改项。

## 4. A · 资产与自动画质（15）

| ID | 项 | 分 | 评分锚点 |
|---|---|---:|---|
| A1 | glTF 合规 | 4 | 0：有 error；2：0 error 但 warning ≥10；4：0 error 且 warning ≤9 |
| A2 | GLB 加载 | 2 | 每 1 件 404/解析失败扣 1，最低 0 |
| A3 | 资产落地 | 4 | 0：比例/朝向明显错误、穿模或漂浮；2：能用但材质/尺度需手工修；4：比例、朝向、材质、接触面均成立 |
| A4 | 技术画质（自动） | 5 | 清晰度、对比、信息熵、色彩丰富度归一化均值；仅作回归信号，不替代美术判断 |

A3 逐件检查：`herbal-cabinet`、`dengzi-scale`、`celadon-bowl`、`nine-palace`、`stone-bridge`、`six-realm-wheel`。

A4 由 `visual_score.py` 产出；装了 pyiqa 时优先用 MUSIQ / CLIP-IQA+ / NIQE / TOPIQ-NR，没装时用轻量像素统计。**无论哪种，A4 只占 5 分，不能单独决定通过。**

## 5. B · 美术十项（50）

每项沿用旧版 0–4 分：

- 0 = 有证据的严重失败
- 1 = 明显问题
- 2 = 基本可用但需修改
- 3 = 符合目标
- 4 = 有证据的出色实现
- 无证据 = `n/a`，从分母剔除，不以未知推断合格

折算：**每项得分 ÷ 4 × 5 = 该项 5 分制得分**。十项合计 50 分。

| 项 | 检查问题 | 所需证据 |
|---|---|---|
| B1 视觉焦点与构图 | 玩家首先看到什么？主目标是否被装饰抢走？轮廓、留白、前中后景是否支持目标？ | 原图、目标说明 |
| B2 灯光与可读性 | 主辅光是否有来源？暗部保留必要信息？高光、雾、辉光是否吞掉线索？ | 原图，关键点近景 |
| B3 材质与表面 | 金属、石、木、纸是否可区分？尺度、粗糙度、磨损是否可信？ | 原图、局部近景；截图不证明真实 PBR 参数 |
| B4 色彩与情绪 | 主辅色、冷暖和饱和度是否符合本场情绪？强调色是否有效？ | 原图、参考图 |
| B5 空间与尺度 | 建筑、家具和道具比例是否可信？空间层次、遮挡和密度是否合理？ | 多机位；精确尺寸需引擎数据 |
| B6 题材与叙事 | 关键道具、建筑语汇和生活痕迹是否服务剧情？是否出现违约物件？ | 项目美术要求、截图 |
| B7 跨场景一致性 | 材质、细节密度、时代语汇是否连贯，同时保留每关差异？ | 至少两场景，缺失则 n/a |
| B8 玩家导航与交互辨识 | 实际机位能否看清可走路线、出口和可交互物？不会把装饰当线索？ | 入口/交互点/出口玩家机位；概念图 n/a |
| B9 HUD 与反馈融合 | 文字是否可读？遮挡是否合理？操作前后反馈是否明确？ | HUD 截图和状态对照；无 HUD/状态证据 n/a |
| B10 画面完成度 | 穿模、悬浮、贴图拉伸、接缝、阴影错误、重复堆砌是否破坏体验？ | 原尺寸截图、多机位；时序问题需连续帧 |

## 10. 《还魂路引》来源与例外（沿用旧版）

权威来源：项目根目录 `场景生图提示词_v3_恐怖版.md`；本表只是评审摘要，来源变化时先重读来源。

- 基调：写实的明清阴司衙署；主要材质为氧化青铜、老榆木、青灰石板、宣纸、做旧织物。来源含黄铜、药材、花、水等剧情必需物，不能机械地以五种词族否决。
- 共性：小面积朱砂点缀，克制、无血腥；七关靠材质和建筑语汇连贯，不强迫所有关卡同色同光。
- 四殿：暖棕、药草绿，柜台暖光与柜体冷光，近景网格，私密温情。
- 五殿：近黑与九盏灯点，高位九宫布局，孤独安静。**大量暗像素是设计意图**；关键交互仍须可读。不能因近黑比例高自动判失败。
- 六殿：乳白雾、彼岸红，室外桥与对角线，释放犹豫。**允许大面积彼岸红**；不能直接套用朱砂 ≤5% 规则。
- 来源的“无人物、无清晰文字”只约束生图参考图；真实游戏的谜题文字和 HUD 应可读，不能照搬模糊字规则。
- 六殿花色与朱砂像素相似，脚本无法分割语义对象，**是否违反 5% 点缀必须人工确认**。
- 五殿俯视、六殿对角线等机位冲突时，概念图按本场具体机位优先；实际游戏按玩家相机验证。

## 11. 证据要求（强制）

每条评分必须同时给出：

1. `evidence`：截图文件名 + 区域描述，或 `文件:行号`，或命令输出片段。
2. `reason`：一句话说明为什么不是更高/更低档。
3. 无法核实的项写 `n/a`，不得猜分；`n/a` 从分母剔除后折算。

## 12. 扣分与打回

- **P0**：硬门槛失败；或任一维度得分 < 60%。
- **P1**：维度 60%–79%；或单个检查项连续两次未修。
- **P2**：纯观感优化，不影响演示闭环。

打回条件：`总分 < 80` 或 `存在 P0`。

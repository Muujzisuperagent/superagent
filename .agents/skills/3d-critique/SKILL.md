# 3D 游戏画面评审

本技能借鉴 Impeccable critique 的独立评估、证据合成、问题分级与存档方法；是独立改编，不调用或冒充原版网页检测器。使用前向用户说明正在使用本技能。

## 输入与边界

1. 确定项目根目录、场景名、版本、图片绝对路径、用途（概念图 / 引擎画面 / HUD）、参考图和目标玩家视角。已有信息直接使用；缺失项记录未知，不编造。
2. 读取本技能 references/rubric.md，以及项目现有美术要求；《还魂路引》默认以项目根目录的 场景生图提示词_v2.md 为来源。项目要求优先于通用偏好。其他项目不得继承《还魂路引》的色板与题材限制。
3. 无图片时可以配置评审流程和验证工具，但不得给真实场景评分或宣称已通过视觉验收。
4. 图片必须实际打开查看。主观判断需要支持图像输入的模型与工具链；工具能返回图片不代表每个模型都能理解图片。无法看图就明确报告阻碍。
5. 概念图不证明可游玩。至少需要入口、主要交互点、出口三个实际玩家机位才能评审导航；走位、闪烁、眩晕与性能需要连续帧、操作证据或引擎数据。没有证据填“未验证”。

## 独立评估

在 DSH 使用两个独立子代理，各自传入完整路径、项目要求、角色和输出约定。不要用 fork 传入另一份评估结果，不同时操作单一桌面窗口。

- A：只看原图与参考图，不接触脚本输出；按 rubric 先完成视觉判断，记录优点、问题、位置、影响、修改建议、置信度。
- B：执行 scripts/audit_img.py，检查输入分辨率、透明度、量测方法和统计；不看 A 输出，不打审美总分。输出数值、候选异常和局限。
- A 完成后再由 Lead 读取 B，与 A 合成。若无子代理能力，则先封存 A 后跑 B，并在报告注明“单代理顺序评审，未实现独立隔离”。不要声称独立双评估已经运行。
- 截图采集另走 agent-desktop 技能；已有图片直接读取。不启动新服务器，不运行网页 DOM 检测器。

## 运行像素体检

使用带 Pillow 和 numpy 的 Python（DSH 可先 load_workspace_dependencies 取得解释器绝对路径）：

```powershell
& '<python.exe>' '<skill目录>/scripts/audit_img.py' '<截图.png>' --scene '一殿' --out '<报告目录>/pixels.json'
```

支持多个图片路径；--scene 可选值为 序厅、一殿、二殿、三殿、四殿、五殿、六殿；不传则不套用本项目告警。量测原尺寸、不缩图，仅接受单帧 PNG/JPEG/WebP/BMP，透明像素按 alpha 加权；不覆盖输入。色板距离使用 sRGB 转 CIELAB 后的 ΔE76，阈值 20 为可解释的启发式，不是色彩校准标准。渲染灯光、后处理与曝光都会改变像素颜色；相似红色不能区分朱砂道具和彼岸花。所有告警需人工复核，禁止自动打回。

## 合成报告

保存到项目根目录 评审/<场景>/<版本>/review.md，并把量测 JSON 放在同目录；先检查已有文件，避免覆盖历史，必要时用新版本目录。报告用相对图片路径或绝对图片路径定位证据。

报告结构：
- 方法、图片/机位/版本、参考来源、缺失证据。
- 结论：通过 / 修改后复审 / 证据不足；注明这是视觉评审，不代表功能和性能验收。
- rubric 的十项 0–4 分，未验证项填 n/a；总分分母为已评分项数 ×4，不设自动通过线。概念图不能给导航和交互反馈打满分。
- 2–3 个可保留的优点；最多 5 个优先问题。
- 每个问题：P级、场景/机位/画面区域、观察到的事实、影响、具体动作、复验条件、置信度；数字仅在对应量测支持时引用。
- 像素证据：数值、参数、被人工接受/驳回的告警及理由。
- 未验证事项与下一轮所需证据。

P0：阻断核心交互或严重画面故障且有实际证据；P1：主目标难以辨识、显著风格违约；P2：局部光照、材质或构图问题；P3：微调。不要因单个像素比例直接定 P0/P1。

只评审，不自动修改场景。给场景制作 Bot 的交接使用“位置 → 动作 → 复验条件”；Lead 再派发修改任务。DSH 队友可用 send_message 沟通和共享文件交接；Agent Teams 与外部聊天平台的 Bot 群聊是不同机制。

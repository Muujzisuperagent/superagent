# 3D 画面评审标准

每项 0–4：0=有证据的严重失败，1=明显问题，2=基本可用但需修改，3=符合目标，4=有证据的出色实现。无证据=n/a，不以未知推断合格。评分是有理由的主观判断，不是测量单位；不按像素数据自动算分。

| 项 | 检查问题 | 所需证据 |
|---|---|---|
| 1 视觉焦点与构图 | 玩家首先看到什么？主目标是否被装饰抢走？轮廓、留白、前中后景是否支持目标？ | 原图、目标说明 |
| 2 灯光与可读性 | 主辅光是否有来源？暗部保留必要信息？高光、雾、辉光是否吞掉线索？ | 原图，关键点近景 |
| 3 材质与表面 | 金属、石、木、纸是否可区分？尺度、粗糙度、磨损是否可信？ | 原图、局部近景；截图不证明真实PBR参数 |
| 4 色彩与情绪 | 主辅色、冷暖和饱和度是否符合本场情绪？强调色是否有效？ | 原图、参考图 |
| 5 空间与尺度 | 建筑、家具和道具比例是否可信？空间层次、遮挡和密度是否合理？ | 多机位；精确尺寸需引擎数据 |
| 6 题材与叙事 | 关键道具、建筑语汇和生活痕迹是否服务剧情？是否出现违约物件？ | 项目美术要求、截图 |
| 7 跨场景一致性 | 材质、细节密度、时代语汇是否连贯，同时保留每关差异？ | 至少两场景，缺失则n/a |
| 8 玩家导航与交互辨识 | 实际机位能否看清可走路线、出口和可交互物？不会把装饰当线索？ | 入口/交互点/出口玩家机位；概念图n/a |
| 9 HUD与反馈融合 | 文字是否可读？遮挡是否合理？操作前后反馈是否明确？ | HUD截图和状态对照；无HUD/状态证据n/a |
| 10 画面完成度 | 穿模、悬浮、贴图拉伸、接缝、阴影错误、重复堆砌是否破坏体验？ | 原尺寸截图、多机位；时序问题需连续帧 |

## 《还魂路引》的来源与例外

权威来源：项目根目录 场景生图提示词_v2.md；本表只是评审摘要，若来源变化应先重新读来源。

- 基调：写实的明清阴司衙署；主要材质为氧化青铜、老榆木、青灰石板、宣纸、做旧织物。来源本身也含黄铜、药材、花、水等具体物件，不能机械地以五种词族否决剧情必需物。
- 共性：小面积朱砂点缀，克制、无血腥；七关依靠材质和建筑语汇连贯，不能强迫所有关卡同色同光。
- 序厅：暖灰黄、旧纸色，冷窗光与暖灯，狭长、偏心透视，日常官僚感。
- 一殿：青铜绿、墨蓝，烛光与镜面冷光，对称、仪式感，镜内无人脸。
- 二殿：黄铜金、淡天青，天光柱与底光，挑高仰视，称量和压迫感。
- 三殿：褐黄、纸灰，窄侧光、收束纵深、密集逼仄，翻查感。
- 四殿：暖棕、药草绿，柜台暖光与柜体冷光，近景网格，私密温情。
- 五殿：近黑与九盏灯点，高位九宫布局，孤独安静。大量暗像素是设计意图；关键交互仍须可读。
- 六殿：乳白雾、彼岸红，室外桥与对角线，释放犹豫。允许大面积彼岸红；全画面红色不能直接套用朱砂≤5%的规则。

来源的通用“人眼高度”与二殿仰视、五殿俯视有冲突，概念图按本场具体机位优先，实际游戏按玩家相机验证。来源的“无人物、无清晰文字”用于生图参考图；真实游戏的谜题文字和HUD应可读，不能照搬模糊字规则。六殿花色与朱砂像素相似，脚本无法分割语义对象，人工确认才可判是否违反5%点缀限制。
